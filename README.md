# LOTUS SI Composer

A static, browser-based editor for the [Supporting Information structure–organism table](https://github.com/lotus-initiative/lotus-manuscript-isnptta/tree/main/si). No server, build step, account, or package installation. It exports a tab-separated table with the 13 columns, in order, from `si/structure_organism_template.tsv`.

## Use

1. Open the site and add one compound–source-organism occurrence per card. The compound number, name, isomeric SMILES and organism are required; the article DOI is **optional**. Include known compounds re-isolated in the study.
2. Use [LOTUS Draw](https://lotus-initiative.github.io/lotus-explore-rs/draw/) to draw a structure, copy its **isomeric SMILES**, and paste it into the SMILES field. Drawing opens separately; it does not automatically transfer a structure.
3. To reuse a value (e.g. organism, DOI, voucher, place, date or evidence), enter it and click **Pin for next** beside that field. New cards copy pinned values; editing a pinned field updates what future cards inherit. Click **Pinned for next** to unpin. Number, name and SMILES are deliberately not pinnable. Pins and records persist in this browser; **Clear draft** clears both.
4. For a part/condition or evidence term, choose the appropriate ontology, search for a term (or CURIE), and click a live [EMBL-EBI Ontology Lookup Service](https://www.ebi.ac.uk/ols4/) result. PO, FAO, UBERON, BTO, ENVO and RO are offered for parts/conditions; CHMO and ECO for evidence. Evidence accepts multiple terms. Verified identifiers can also be typed manually. For example, search **leaf** in PO and select `PO:0025034`.
5. For **collection place**, search [Wikidata](https://www.wikidata.org/) by name and choose a place from the described results to insert a `wd:Q…` identifier. The search is not type-restricted: non-places can appear, so verify the description and identifier. For a precise collection site, click **Pick on map…** then click the map, or enter valid latitude and longitude and press **Use coordinates**. This writes an [RFC 5870](https://www.rfc-editor.org/rfc/rfc5870) URI such as `geo:46.805556,7.161267` into the existing `collection_place` column (an extension beyond the template's `wd:` / `geonames:` examples). Named places and exact coordinates are alternative values for this column, not simultaneous fields. Do not pin exact coordinates for unrelated samples.
6. Inspect the live **TSV preview** below the cards, then download the TSV. Preview and download use the same serialization, including tab/newline quoting. The browser checks required fields, any nonblank DOI's shape and unique compound numbers; it **does not validate chemistry, taxonomy, place identity, ontology semantics or whether the DOI resolves**. Review stereochemistry, selected labels, vouchers and the downloaded file before submitting. `lotus curate file.tsv --format tsv` currently handles **name, smiles, organism and doi when present**, not the extra context columns.

Drafts are saved to this browser's `localStorage`. They are not synchronized and can be removed by clearing browser data. Export a TSV for a durable copy. No draft data is sent to this site: only your term search goes to OLS and your named-place search goes to Wikidata. Opening the map fetches Leaflet from unpkg and visible OpenStreetMap tiles (with attribution); clicking the map does **not** send coordinates to a geocoder. Searches and map tiles need internet access, but manual CURIE/coordinate entry and TSV export do not. The map is loaded only on demand. Avoid searching or opening maps around sensitive collection sites if third-party traffic is a concern.

**Ontology IDs need checking.** Some worked examples in the manuscript describe `PO:0025025` as “root bark”, but OLS currently labels that ID **root system**; `FAO:0000011` is currently **mycelium**, not “basidioma”. This editor intentionally uses live ontology labels rather than hard-coded example labels. If a label does not match your sample, do not reuse the example ID without verification.

## Run and publish

Serve locally with `python3 -m http.server 8000` and visit `http://localhost:8000/`. Use an HTTP(S) origin rather than `file://` so map tile requests carry a valid Referer. Assets use relative URLs so the site also works at a GitHub Pages repository subpath.

To publish, push the repository to GitHub, enable **Settings → Pages → Build and deployment → Source: GitHub Actions**, and push to `main`. The workflow in `.github/workflows/pages.yml` deploys the repository root as a static Pages artifact. No secrets or backend are needed. On a repository named `jnp-si-ui` under `lotus-initiative`, the expected URL is `https://lotus-initiative.github.io/jnp-si-ui/` (depending on repository ownership and Pages settings).
